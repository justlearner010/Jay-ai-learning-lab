### Agent 笔记：本次概念纠正（重要，防以后重复错）
用户口述有两个需要纠偏的点：

1. **前向传播顺序说反了**。
   用户说：input → ReLU(把<0变0) → 再加权重 W 和偏差 b → 得到数据。
   正确：input x → **z = W·x + b**（线性变换，先！）→ **a = ReLU(z)**（激活，后！）→ 输出/下一层。
   即权重和偏差是「作用在激活之前」的，ReLU 是作用在 Wx+b 的结果 z 上的。
   用户描述的顺序（先 ReLU 后 Wb）在数学上不成立——ReLU 是对「加权求和+偏置」之后的值做门控。

2. **ReLU 的"作用"定位错了**。
   用户说：ReLU 把 <0 变 0 是为了"减少 noise 噪音"。
   纠正：ReLU 的核心目的**不是降噪**。它是**非线性激活函数**，作用是：
   - (a) 引入非线性——没有它，多层线性变换叠起来还是线性，学不了非线性边界；
   - (b) 缓解梯度消失——x>0 时梯度恒为 1（对比 sigmoid 两端梯度≈0），训练更深更稳定；
   - (c) 顺带产生稀疏性（很多神经元输出 0），稀疏可看作一种轻量正则/效率，但**这不是"降噪"**。
   "把负数砍成 0"是 ReLU 的数学定义，不是它降噪的手段。

3. **用户说对的部分（确认无误）**：
   - 一个输入连多个隐藏单元 H，再到不同输出 y（全连接层：每个隐藏单元有自己的一组 W 行 + b）→ 这是「多层感知机 / 多输出」的正确直觉。
   - dying ReLU：当大量神经元输入恒为负 → 输出恒 0 → 梯度也恒 0 → 参数永不更新 → 神经元"死掉"。用户理解正确。
   - Leaky ReLU：x<0 时给一个很小斜率 α（如 0.01），f(x)=αx，让负值接近 0 但不为 0，梯度非零 → 神经元可复活。用户理解正确。

→ 结论：架构直觉 + dying ReLU + Leaky ReLU 都懂了；卡在"前向顺序"和"ReLU 本职"两个点上，已立 ⬜ 卡点。闭环动作：hand-write 最小前向传播验证顺序。
