## 上午（L5 英语 / 口语流利度方法 · 句子扩展法）

### 学了什么
- 流利度方法：**不要一上来就说完整长句**，而是从"核句（kernel sentence）"起步，通过**重复 + 逐步加从句**扩展。
- 示例链（用户口述）：`I'm curious.` → `I'm curious about things.` → `I'm curious about things because...` → `...which can make me...` etc.
- 核心：多练、多重复，从简单句长出来，而不是硬憋复杂句。

### Agent 订正（语法示例）
- `I'm a curious` ❌：curious 是**形容词**，不能加 a；应为 `I'm curious`（或要名词 `I'm a curious person`）。
- `which can makes me` ❌：情态动词 `can` 后接原形 → `which can make me`。
- `and which` 结构需理清先行词；更干净写法：`I'm curious about things, which can make me...`（一个 which 引导非限制定语从句）或 `...because X, and this makes me...`。
- 方法本身 ✅：这种"核句→加 because/which 分支"的扩展法，正是流利度训练的有效路径（降低认知负荷、建立句型肌肉记忆）。

### 与年度目标的连接
- 此"核句→扩展"流程**正好可被你昨天想的「场景式英语 APP」产品化**：输入一个核句 → APP 引导用户加 because / which 分支 → 生成扩展句并跟读。L5 产出探索与主航道形成闭环。

## 上午（续 · L1 Pi Agent · agent loop 与异步机制，约4h）

### 学了什么
- 读 Pi Agent 的 agent loop 核心，重点在**异步 think** 机制。
- 理解了 `Promise` / `await` 的基本使用策略：调用一个会"稍后才有结果"的操作（如 LLM 返回、工具 I/O）时，用 `await` 挂起当前函数，等结果回来再继续。
- 用户自己的比喻（准确）：像餐厅——客户（调用方）到前台点单，前台把单子交给厨房（异步操作），**挂起一个 promise** 进入 `await`，主线程不阻塞、继续接下一单；厨房做好（promise settle）再回调续做。
- 目标：异步编程让子任务/I-O 不阻塞主线程运行。

### Agent 订正（关键细节）
- **JS/TS 主线程是单线程的**：`async/await` **并不会创建新的子线程**。它靠**事件循环（event loop）+ 微任务队列（microtask queue）**实现"非阻塞"，不是多线程并发。
- 精确过程：`async` 函数同步执行到 `await` 时，**挂起自身**（返回一个 pending promise），把控制权交还事件循环；事件循环转去跑别的已就绪任务。等被 await 的 promise settle，续写部分作为**微任务**被排进队列、择机恢复。
- "厨房"在 Node/浏览器里通常是**运行时的 I/O 子系统**（底层可能用线程池做网络/文件），但**那段不是你的 JS 主线程**；CPU 密集型活儿想真并行得用 Web Worker / worker_threads，不是 `await`。
- 所以你那句"不让子线程阻碍主线程"应改成：**"不让 I/O 等待阻塞主线程"**——await 释放的是主线程的"当前调用栈"，不是 spawn 线程。
- 为什么 agent loop 必须异步：loop 里每轮都要 LLM 网络往返 + 工具调用（多 I/O），全 awaitable；若同步写会卡死整个进程，await 让事件循环在等 LLM 时空出来。

### 概念卡点（待闭环）
- ⬜ 已记入顶部卡点：事件循环 / 微任务 vs 宏任务 / await 挂起-恢复的全链路。用户自述"只是基本了解概念、很多不清楚"——符合 active learning 捕获条件。
