## 上午（L2 实现 / PyTorch 最小 NN 跟练）

### 做了什么
- 跟教程把一段 PyTorch 代码从头敲了一遍，不是只看。流程串起来了：
  1. **造非线性数据**：生成一组非线性（曲线）样本，用来逼网络必须靠非线性激活才能拟合。
  2. **建模+前向传播**：用 Linear 层 + 激活函数（ReLU 之类）搭小网络，输入往前算到输出。
  3. **损失函数**：用 MSE 衡量预测和真值的差距。
  4. **反向传播 + 优化**：autograd 自动算梯度，优化器据梯度更新参数；迭代几步后 loss 下降。
  5. **绘图验证**：把拟合结果画出来，看到网络曲线逐渐贴住原始非线性数据。
- 直观上把"训练一个神经网络的大致过程"跑通了一遍：数据 → 前向 → 算 loss → 反向 → 更新 → 再前向，循环到收敛。

### Agent 连接（冲刺判定）
- 这正好是本周冲刺 #1「PyTorch L1→L2」的 step 0-3：读基础 → hand-write forward → hand-write loss+backward+train loop → 跑通 loss 下降。dashboard 已把 done 标到 [true,true,true,false]。
- **但 L2 的真门是 exit 里的"逐行讲清"**。你跟着教程敲、跑通、看到图，这是真 Implement 的起步，不是 L1 的 Only-Explain。可要确认它不是"手会敲、脑子没走通"，得你能把下面几点用自己的话讲顺（这就是 step 4 的 ⬜ 门）：
  1. 为什么非线性数据必须用激活函数？没有 ReLU 会怎样？

- 讲清这三点，这张卡就翻 ✅，L2 算真正到手。

## 下午（L1 框架 / Pi Agent 三层架构深化）

### 学了什么
- 顺着昨天看清的单向依赖，今天用「依赖漏斗分层法」把三层对上了具体名字与职责：
  - **Pi-AI（最底）**：只调 LLM。你在这层要自己管状态、自己写循环，但它最通用、最不受业务绑定。
  - **Agent core（中间）**：在 Pi-AI 之上叠加，给出"完整的 agent 能力"（循环、状态机、工具调度等）。但工具、入口还要你自己写，所以它适合做成你自己的独立 agent / 工具，而不是开箱即用的产品。
  - **Pi coding agent（最顶）**：三层齐备，就是像 Pi 本身那样的编程助手，可以直接用，也能在其上扩展能力。
- 方向很关键：**依赖只向下**（上层依赖下层，下层不知道上层存在）；越往上越具体、越往下越通用。这就是"漏斗"——底部宽（通用能力），顶部窄（具体业务）。

### 设计原则（他自己的提炼）
- **解耦每层**：不能把能力耦合在一起。实操判据很硬——"假设要换 LM provider，是得重写一整个文件，还是底层已经有通用能力、只改一小块？" 如果换 provider 要动全身，就是耦合了。
- **每层可独立测试**：依赖关系明确，单层能单独跑、单独验证，改起来不会牵一发动全身。
- **易修改 / 易扩展 / 易使用**：这正是 Pi 架构高明的地方——把"通用"和"具体"分层放好，未来换模型、加工具、接新场景都只碰对应那一层。

### Agent 连接（冲刺判定）
- 这依然是 **L1（Explain）**：你把三层关系、依赖方向、设计动机讲得很顺，但代码不是你写的，而且两个 ⬜ 卡点（消费流、async 底层）还没去源码里定位。所以 Pi 这周目标是"L1 稳 → 撞 L2"，今天是在把 L1 底座补厚、补到能讲清"为什么这么分"。
- **L2 的真门没变**：hand-write 一个最小 core loop + 1 个工具 + 接 LLM，跑通一个任务。今天的理解是写它之前必要的地图——等你动手时，这些分层就是你文件该怎么切的直接依据。
- 顺带确认序列化守住了：今天 L2 推力只在上午 PyTorch，下午 Pi 是 L1 稳，全天只推了一个 L2，合规。
