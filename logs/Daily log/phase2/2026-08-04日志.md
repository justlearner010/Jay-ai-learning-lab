## 上午（L1 · 拆解 Pi 架构 + 最简 Pi 实现）

### 做了什么
- **拆了 Pi 的主要层**，并让一个 Agent 生成了一个**最简 Pi**，包含 5 个组件：
  1. **核心 Loop（Core Loop）**：agent 的主循环——接收输入 → 调 LLM → 处理事件/工具 → 决定继续或结束。
  2. **tools 工具层**：agent 可调用的外部能力（函数/API），由 Loop 在需要时调用。
  3. **Event Stream（事件流）**：agent 运行过程中持续产出的一系列事件（token、工具调用请求、工具结果、步骤标记、错误等），以流的形式吐出。
  4. **LLM provider 层**：对具体大模型（如某 API）的抽象/适配层，让上层不关心用的是哪家模型。
  5. **消费流（consumption stream）**：用户表示"不太清楚是什么" → 见下方 Agent 澄清。

### Agent 澄清：消费流是什么（grounded，待你用源码验证）
- 在"事件流"架构里，通常分**生产者 / 消费者**两端：
  - **Event Stream（事件流）= 生产者侧**：agent / LLM 把运行过程写成一串事件，推到流里。
  - **消费流 / Consumer（消费流）= 消费者侧**：在流的另一头，**读取（drain）这些事件并做点什么**的组件。它把事件变成"看得见/用得上"的东西——比如把 token 实时渲染到终端或界面、把步骤写进记忆/日志、触发副作用（发消息、写文件）、或喂给下一个处理阶段。
- 一句话：**Event Stream 是"agent 说了什么"，消费流是"谁来接住并把它变成结果"**。没有消费流，事件就只是流过、没人处理。
- ⚠️ 这是按通用事件流 agent 模式推断的解释（你这次没贴 Pi 源码）。**闭环动作**：去 Pi 源码里找 `consumer` / `subscribe` / `EventStream` 的消费端，确认它的消费流到底 drain 了什么、做了什么——搞懂就翻 ✅。
