## 2. 部署 gotcha
- `docker compose up` 必须在仓库的 `docker/` 子目录下执行 —— 根目录没有 compose 文件，在根目录跑会起不来。
- 正确步骤：
  ```bash
  cd Dify/docker
  cp .env.example .env
  docker compose up -d
  ```
- 第一次在根目录跑导致失败，不是操作错，是仓库目录约定的坑（很多人第一次都踩）。

## 3. 核心观察 + 纠正：chatbot / 工作流 vs agent
### 我的观察
两者都「定义工作流」，但 chatbot 编辑器自主性（agency）差一些。

### 纠正：差别在「控制权」，不在能力高低
- **工作流 / 聊天助手 = 固定 DAG**：节点按预定顺序执行，到「结束」即停。路径是画死的，可控可调试。
- **智能体 = 自主推理环**：LLM 当决策中心，自己决定下一步调哪个工具、要不要再循环，直到任务完成（底层是 ReAct / function-calling 循环）。
- Dify 创建应用时可选「智能体」类型，底层就是 ReAct。所以结论不是「Dify 的 agent 不行」，而是它两种都给：**聊天助手是确定性那条，智能体是自主那条**。

### 工程权衡（该记牢）
| 维度 | 工作流 | 智能体 |
|---|---|---|
| 可预测性 | 高 | 低 |
| 调试难度 | 易 | 难 |
| token 成本 | 可控 | 可能失控（死循环烧钱） |
| 适合场景 | 步骤明确的任务 | 路径未知、需应变 |
