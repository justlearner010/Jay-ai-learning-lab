# 待验证假设

## H1：分层汇报可以减少人的无效中断

**命题**：当 Coordinator 能正确处理授权内问题并压缩进度时，人主动查看底层日志和被 Agent 请求介入的次数会下降。

**不能接受的代价**：关键风险被过滤掉，或人因摘要失真做出错误决策。

## H2：明确的责任和写入边界可以减少冲突

**命题**：当子任务有明确输入、写入范围、验收标准和停止条件时，多 Agent 的重复劳动、产物覆盖和合并冲突会减少。

## H3：独立验证能阻止局部错误向上传播

**命题**：在 Specialist 交付后增加独立验证关卡，能在聚合之前发现更多可验证错误，并减少整体返工。

**边界**：不将多一个 LLM 的相同意见当成独立证据。

## H4：分层系统能更快局部化失败

**命题**：当任务、权限和状态边界清晰时，单个 Agent 的失败可以被限制在子任务内，不需要整个系统从头重启。

## H5：Coordinator 可能同时成为价值来源和单点瓶颈

**命题**：Coordinator 可以降低人的信息负担，但也可能因为错误拆解、摘要失真、上下文过载或调度延迟降低整体稳定性。

这不是需要被排除的干扰项，而是项目必须主动测量的核心风险。

## H6：不是所有任务都从多 Agent 中受益

**命题**：对高度耦合、必须共享同一状态、难以独立验证或任务规模很小的工作，多 Agent 的协调成本会超过其收益。

## H7：良好的升级策略比更多沟通更能提高稳定性

**命题**：清晰的越权、风险、冲突和无法验证条件，比让 Agent 频繁自由讨论更能阻止错误继续扩大。

## 第一阶段优先级

第一个真实实验只优先验证 H1、H2 和 H5：

1. 层级是否减少了人的无效介入；
2. 边界是否减少了冲突；
3. Coordinator 带来的新成本是否低于它解决的成本。
