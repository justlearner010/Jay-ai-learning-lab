# 未来实验路线

## 实验前置条件

进入本项目前，先完成一个单 Agent 项目，并能回答：

- loop 何时继续、停止或请求人工确认；
- 工具权限和写入边界如何限制；
- 状态如何保存、恢复和审计；
- 失败如何重试，什么时候不应重试；
- 结果如何用测试或其他证据验证。

如果这些问题还没有在单 Agent 中解决，多 Agent 只会将失败从一个执行器复制到多个执行器。

## 实验任务的选择条件

选择一个同时满足以下条件的真实任务：

- 可拆分为 2–3 个边界清晰的子任务；
- 子任务可以独立产生证据；
- 最终结果可以聚合和端到端验证；
- 存在一定信息过滤和异常升级需求；
- 用单 Agent 仍然可以完成，以便建立基线。

候选场景可以是资料研究与综合、互不重叠的代码审查、数据分区处理，或有清晰模块边界的小型项目。不优先选择多个 Agent 同时修改同一份高耦合代码的场景。

## 三组对照

### A. 单 Agent 基线

一个 Agent 获得完整任务，自己规划、执行和验证。

用途：测量不增加协调复杂度时的成本与稳定性。

### B. 扁平多 Agent

多个 Agent 直接接收人的任务，共享状态或自由沟通，人负责聚合与处理冲突。

用途：观察多 Agent 数量增加本身带来的信息和管理成本。

### C. 分层多 Agent

人只与 Coordinator 对接；Coordinator 通过结构化子任务合同调度 Specialist，并在验证后汇总或升级。

用途：验证层级、边界和信息过滤是否能够降低协调成本。

## 核心指标

### 人的管理成本

- 人被请求介入的次数；
- 人主动查看底层日志的次数；
- 人用于理解状态、解决冲突和重新指挥的时间；
- 人是否能说清当前状态与关键风险。

### 协调质量

- 重复执行的子任务数；
- 写入范围或产物冲突数；
- 因上下文缺失而返工的次数；
- 子任务交付是否附带可验证证据。

### 信息过滤质量

- 底层信息量与人类汇报量的比例；
- 重要异常是否被正确升级；
- 摘要中是否出现事实失真或不恰当确定性；
- 人是否能从摘要追溯到原始证据。

### 系统稳定性

- 端到端任务成功率；
- 在预设时间或资源边界内完成的比例；
- 单个 Agent 失败后是否可以局部恢复；
- 未被发现的错误数；
- 从失败到定位责任与恢复执行的时间。

### 协调税

- 额外模型调用、token、延迟与工具调用；
- Coordinator 处理状态与摘要的时间；
- 多 Agent 引入的合并、等待和重试成本。

## 成功标准

分层多 Agent 只有同时满足以下条件，才证明层级在当前任务中有价值：

- 减少人的无效中断与状态整理成本；
- 不增加关键风险遗漏；
- 减少冲突、重复执行或全局重启；
- 保持或提高最终结果质量；
- 节省的管理与返工成本高于新增协调税。

## 停止或回退条件

- Coordinator 经常隐藏或曲解关键信息；
- 层级带来的延迟与上下文复制超过收益；
- 任务无法形成稳定的子任务边界；
- 大部分问题仍然必须直接升级给人；
- 单 Agent 能以更低成本达到相同或更好结果。

回退到单 Agent 不是失败，而是对多 Agent 适用边界的有效学习结果。
